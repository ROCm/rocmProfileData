# RPD Query Cheat Sheet

## Time & Units

All `start` / `end` values are **nanoseconds**. Convert with:

| Unit | SQL expression |
|------|---------------|
| microseconds | `(end - start) / 1000` |
| milliseconds | `(end - start) / 1e6` |
| seconds | `(end - start) / 1e9` |

## Views (denormalized, ready to query)

| View | Source | Key columns |
|------|--------|-------------|
| `api` | rocpd_api + strings | `id, pid, tid, start, end, domain, category, apiName, args` |
| `op` | rocpd_op + strings | `id, gpuId, queueId, sequenceId, start, end, description, opType` |
| `kernel` | api_ops + op + kernelapi | `id, gpuId, queueId, start, end, duration, stream, grid*, workgroup*, kernelName` |
| `copy` | copyapi + api | `id, pid, tid, start, end, apiName, stream, size, kind, dst, src` |
| `copyop` | api_ops + op + copyapi | `id, gpuId, queueId, start, end, duration, stream, size, apiName` |
| `busy` | op aggregated | `gpuId, GpuTime, WallTime, Busy` (fraction 0-1, in ns) |
| `top` | op aggregated | `Name, TotalCalls, TotalDuration_us, Ave_us, Percentage` |
| `callStack_exclusive_name` | ext_callstack (depth=0) | `parent_id, apiName, args, cpu_time, gpu_time` |
| `callStack_inclusive_name` | ext_callstack (all depth) | `parent_id, apiName, args, cpu_time, gpu_time` |
| `napi` / `nop` | api/op with multi-node stride math | splits `pid` → `node + pid`, `gpuId` → `node + gpuId` |

Common domains: `hip`, `miopen`, `torch`, `rpd_tracer`.

Categories: `driver`, `function`, `overhead`, `user_scope`, `backward_function`.

## Key Query Patterns

### 1. Time-window scoping

Scope to a marker or range by joining `rocpd_api_ops` on the time window:

```sql
-- Find all GPU ops dispatched by API calls that fall within a time window
SELECT B.*
FROM api A
JOIN rocpd_api_ops O ON O.api_id = A.id
JOIN op B ON B.id = O.op_id
WHERE A.apiName = 'hipLaunchKernel'
  AND A.start BETWEEN <window_start> AND <window_end>;
```

User markers appear as `apiName = 'UserMarker'` with the label stored in `args`.
rlog / ROCTX annotations use the `domain` / `category` / `apiName` fields directly.

### 2. Call hierarchy (from ext_callstack)

```sql
-- Top-10 exclusive CPU time
SELECT apiName, args, cpu_time/1e6 AS ms
FROM callStack_exclusive_name
ORDER BY cpu_time DESC LIMIT 10;

-- Top-10 inclusive GPU time attributed to each caller
SELECT apiName, gpu_time/1e6 AS gpu_ms
FROM callStack_inclusive_name
ORDER BY gpu_time DESC LIMIT 10;
```

The `ext_callstack` table records every parent→child edge with `depth`,
`cpu_time` (time spent in that frame only), and `gpu_time` (associated GPU work).
See `rocpd/call_stacks.py` for generation logic.

### 3. GPU utilization

```sql
-- Per-GPU busy fraction (from built-in view)
SELECT * FROM busy;

-- Queue depth: count concurrent ops at any moment using self-join
SELECT A.id, A.start, A.end, A.description,
       (SELECT COUNT(*) FROM op B
        WHERE B.queueId = A.queueId
          AND B.start < A.end AND B.end > A.start) AS depth
FROM op A
ORDER BY depth DESC LIMIT 5;
```

### 4. Kernel performance ranking

```sql
SELECT kernelName, COUNT(*) AS launches,
       SUM(duration)/1000 AS total_us,
       AVG(duration)/1000 AS avg_us
FROM kernel
GROUP BY kernelName
ORDER BY total_us DESC LIMIT 10;
```

### 5. Copy bandwidth

```sql
SELECT apiName, SUM(size) AS total_bytes,
       SUM(size)/SUM(end-start)*1e9 AS GBps
FROM copy
GROUP BY apiName;
```

## Args Column (json_extract patterns)

The `args` column is JSON. Use `json_extract(args, '$.key')`.

### hip domain
```json
{"size":2097152, "dst":"0x7fdfa9000000", "src":"0x0"}
```
- `hipMalloc` → `$.size`, `$.dst`
- `hipLaunchKernel` → `$.args` is a hex-encoded pointer blob (not useful)

### torch domain
```json
{"seq":1002, "op_id":31207, "sizes":[[32,256,14,14]]}
```
- `$.op_id` → join to `op.id` to link CPU call → GPU op
- `$.sizes` → tensor shapes, e.g. `json_extract(args, '$.sizes[0]')`
- `$.seq` → sequence number within a step

### miopen domain
```json
{"handle":"stream: 0, device_id: 0", "xDesc":"{32,3,224,224}, ...",
 "convDesc":"conv2d, miopenConvolution, ..., {3,3}, {2,2}, {1,1}, ...",
 "algo":"1", "workSpaceSize":"0"}
```
- `$.xDesc` / `$.yDesc` / `$.wDesc` → tensor shape strings
- `$.convDesc` → filter/stride/padding in readable form
- `$.algo` → algorithm index
- `$.workSpaceSize` → workspace bytes

### user_scope / rlog annotations
Same as torch: `$.seq`, `$.op_id`, `$.sizes`.
NCCL ops: `nccl:all_gather`, `nccl:all_reduce` with `$.sizes` showing element counts.
